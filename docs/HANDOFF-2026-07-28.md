## Observed peak market cap

A peak is a fact about a *token*, not a snapshot, and is only knowable once the
run is over. `netlify/functions/peak-backfill.ts` runs hourly and reads each mint
**exactly once**, while it is between 24 hours and 5 days old.

- Lower bound: Dune's window is exactly 24.0h wide (measured, hard ceiling across
  1,313 tokens), so by 24h the token has left the live cohort and its run is done.
- Upper bound: an explicit product decision — "anything more is irrelevant, this
  space moves fast and people move on."
- Peaks live only in `observedPeaks`, keyed by mint, joined onto tokens at read
  time in `/api/graduated`. Token rows never carry a peak, so stored snapshots
  are never rewritten.
- The queue is the database itself: any mint lacking a reading stays eligible, so
  a token cannot fall out of the work set by leaving Dune's window.

Request shape (verified against the live API, see
`netlify/functions/_shared/solana-tracker.ts` for the full rationale):
`type=1h`, `time_from`/`time_to` (snake_case — camelCase is silently ignored),
`marketCap=true`, `removeOutliers=false`. **A response caps at 2000 candles and
returns the newest ones**, so `1m` silently loses the early history where peaks
occur. Do not "optimise" this back to `1m`.

Usage is self-limiting — one read per mint, ~15-45 arrivals/day — so it stays
inside the free 2,500/month with no budget accounting. The whole budget subsystem
(`observed_peak_budget.ts`, `providerUsage`, `reserveRequests`) was deleted.

## Known-unresolved, shipped deliberately

- **Union writing bypasses the collapse guard.** `preserveExistingTokens: true`
  skips `evaluateSnapshotReplacement`. Safer for data — it merges and never
  deletes — but it removes the alarm. Arrivals have already fallen from a ~44/day
  30-day mean to ~15/day with health green throughout. A degraded-cohort signal
  is the highest-value next piece of work.
- **All operational Convex mutations are public and unauthenticated**
  (`storeSnapshot`, `duneMetadata.update`, `syncRuns.*`, `observedPeaks.record`),
  and the scheduled endpoints are publicly invokable — which is how the
  production backfill above was triggered. Needs a plan and sign-off before any
  change; it touches auth.
